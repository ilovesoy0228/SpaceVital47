> 이 파일을 프로젝트의 `docs/MEASUREMENT_CASES.md`로 두고, 같은 ID(C001~C100)로 `tests/cases.test.js`를 만든다.
> 모든 수치 임계값은 [설계 선택]·D0(근거 없음)이다. 근거가 있는 것처럼 화면·문서에 쓰지 않는다.

## 0. 공통 정의 (케이스가 의존하는 규칙)

| 용어 | 정의 |
|---|---|
| 임무일 D | `S.missionDay`. 정수. UI에서 ◀ ▶ 와 "하루 마감"으로 바꾼다. |
| 어제 | **D−1 날짜의 기록**만 뜻한다. 배열의 마지막 항목이 아니다. D−1 기록이 없으면 "어제 기록 없음". |
| 체크인 기준선 | 기록이 있는 날 중 **처음 14일**의 평균. 14개 미만이면 `null`, 화면에는 "수집 중 n/14". 오늘은 포함하지 않는다. |
| 카메라 기준선 | 유효 카메라 기록이 있는 날 중 **처음 14일**의 부위별 중앙값. n<3이면 Δ 표시만 하고 규칙은 발동하지 않는다(n=1은 Δ 자체를 숨김). n=14에서 확정, 이후 고정. |
| 유효 기록 | 품질 게이트를 통과한 기록. 실패 기록은 저장하되 추세·Δ·규칙에서 제외하고 "품질 미달"로 표시한다. |
| 같은 날 재촬영 | 그날의 유효 기록 중 **마지막 것**이 그날 값. 이전 것은 `superseded`로 남긴다. 추세 점은 하루 1개. |
| 부위(ROI) | forehead, cheekL, cheekR, eye(눈 주변), lips. 얼굴 종합 `face` = 유효한 얼굴 ROI(forehead, cheekL, cheekR)의 **중앙값**. |
| 카메라 규칙 상한 | 카메라 단독 규칙 최대 레벨 1. 증상 결합 규칙 최대 레벨 2. 카메라는 카드를 만들지 않는다. |
| 합성 표시 | 시연용 합성 기록은 `synthetic:true`. 화면에 "합성"이라고 표시. 실제 촬영이 같은 날 값을 대체한다. |

### 테스트 픽스처 (tests/fixtures.js에 만들 것)
- 기본 피부색 Lab (L=65, a=14, b=18) — 합성 값, 실제 피부 분포 아님.
- `skinFrame({ dA:{forehead,cheekL,cheekR,eye,lips}, Lscale, spec:{roi:비율}, bg:[R,G,B], seed })` → 480×640 RGBA. ROI별로 목표 Δa*를 만드는 Lab→sRGB 역변환 포함. 시드 고정 잡음 σ≈1 RGB.
- `makeVideoSamples({ bpm, fs, seconds, drops, lightVar, noise })` → rPPG 샘플.
